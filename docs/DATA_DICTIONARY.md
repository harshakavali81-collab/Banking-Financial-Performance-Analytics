# Data dictionary and grain

## Keys and source columns

| Table | Key | Fields and meaning |
|---|---|---|
| branches | branch_id | branch_name, city, region: fictional service locations |
| customers | customer_id | customer_name: anonymous demo label; age: years; occupation: categorical or Unknown; annual_income: INR/year; credit_score: simulated integer 300-900; home_branch_id: branch FK |
| accounts | account_id | customer_id/branch_id: FKs; account_type: Savings/Current; open_date: date; opening_balance: INR on 1 Jan 2025 |
| transactions | transaction_id | account_id: FK; transaction_date: date; transaction_type: external account movement; amount: positive INR; channel: Mobile/Internet/ATM/Branch; signed_amount: credit positive, debit negative; customer_id/branch_id: validated enrichment |
| loans | loan_id | customer_id/branch_id: FKs; loan_type: category; origination_date: date before reporting year; original_principal: INR; annual_interest_rate: decimal; tenure_months: scheduled equal-principal tenor |
| repayments | payment_id | loan_id: FK; due_date/payment_date: dates (payment_date blank if unpaid); principal_due/interest_due/principal_paid/interest_paid: INR; payment_status: Paid/Unpaid |
| account_snapshots | snapshot_date + account_id | balance: INR at month-end |
| loan_snapshots | snapshot_date + loan_id | outstanding: INR unpaid principal; days_past_due: calendar days from oldest unpaid installment to month-end, otherwise zero |
| branch_financials | snapshot_date + branch_id | interest_income: cash received; interest_expense: deposit and wholesale funding cost; fee_income: modeled fees; operating_expense: modeled operating costs, all INR |

Account and loan snapshots are stocks. Transactions, repayments and financial income/expense are period flows. Loan repayments are a separate ledger and do not imply a debit from these synthetic deposit accounts. There are no paired internal transfers; Transfer In/Out means transfers to/from outside this dataset.

## Cleaning contract

Drop exact transaction duplicates only. Reject non-positive/invalid amounts, missing/invalid dates and unknown account IDs. Preserve rejected records with a reason in `data/quarantine/transactions.csv`. Normalize recognized channel text and use Unknown for missing occupations. Unique IDs, nonnegative balances and credit-score range are checked by SQLite constraints. No unverified numeric value is imputed.

## Source

All tables are generated by `src/pipeline.py`, seed 81. No real bank, customer, personal data or public-bank performance data is represented. All accounts/customers/loans exist before the start of 2025, so customer acquisition and new loan disbursement trends cannot be inferred.
